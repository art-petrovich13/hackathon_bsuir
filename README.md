NPA Assistant

AI-ассистент для сравнения нормативных правовых и локальных нормативных актов

Проект разработан в рамках хакатона БГУИР.

NPA Assistant помогает быстро анализировать изменения между двумя редакциями нормативного документа. Пользователь загружает старую и новую версии документа, после чего система автоматически выделяет изменения, классифицирует их по смыслу, оценивает уровень потенциального правового риска и предоставляет результаты в удобном веб-интерфейсе.

Проект ориентирован на анализ нормативных правовых актов (НПА) и локальных нормативных актов (ЛНА).

⸻

✨ Возможности

📄 Загрузка документов

Пользователь может загрузить две редакции одного документа:

* старая редакция;
* новая редакция.

Поддерживаются форматы:

* .pdf
* .docx

Максимальный размер одного файла — 50 МБ.

При загрузке документ проверяется по SHA-256 хешу, поэтому повторная загрузка одного и того же файла не приводит к повторному парсингу. (GitHub)

⸻

🔍 Структурный анализ документов

Перед сравнением документы разбираются на структурные элементы.

Система пытается определить:

* главы;
* разделы;
* статьи;
* пункты;
* параграфы;
* обычный текст;
* таблицы.

Для .docx структура определяется на основе стилей заголовков и нумерации.

Для .pdf используется анализ текста, размеров шрифта и структуры документа. Предусмотрены несколько способов извлечения текста с fallback-механизмом при ошибках. (GitHub)

Это позволяет сравнивать не просто два больших текста целиком, а конкретные части документа.

⸻

⚖️ Сравнение редакций

После загрузки двух документов пользователь запускает AI-анализ.

Система создаёт задачу сравнения и передаёт её в Celery для фоновой обработки. Результат сохраняется в PostgreSQL. (GitHub)

Для отслеживания состояния анализа предусмотрен WebSocket:

Frontend

   ▼
FastAPI
   │

Celery Worker

Это позволяет интерфейсу получать информацию о ходе обработки без необходимости постоянно перезагружать страницу.

🤖 AI-анализ изменений

Главная часть проекта — семантический анализ найденных изменений.

AI получает информацию о старой и новой версии конкретного фрагмента и определяет:

Тип изменения

* OBLIGATION_CHANGE — изменение обязательств;
* SCOPE_CHANGE — изменение области применения;
* DEADLINE_CHANGE — изменение сроков;
* SUBJECT_CHANGE — изменение субъекта нормы;
* SANCTION_CHANGE — изменение ответственности/санкций;
* COSMETIC — изменение без существенного смыслового влияния.

Уровень риска

LOW
MEDIUM
HIGH
CRITICAL

Дополнительно AI формирует:

* числовую оценку риска;
* объяснение изменения;
* возможную ссылку на законодательную норму;
* рекомендацию для юриста;
* confidence — уверенность модели в результате. (GitHub)

Например, изменение формулировки с «имеет право» на «обязан» рассматривается как потенциальное изменение обязательства, а изменение санкции может получить высокий или критический уровень риска.

📊 Интерфейс анализа

После завершения анализа пользователь получает несколько представлений результатов.

Изменения

Основной режим позволяет просматривать найденные изменения между редакциями документов.

Изменения представлены с указанием их типа и уровня риска.

Таблица

Все найденные изменения можно просматривать в табличном формате.

Dashboard

Dashboard предоставляет сводную информацию об обнаруженных изменениях и рисках.

В интерфейсе используются графики и визуализация данных.

ПРОКУРОР

Отдельный модуль предназначен для анализа потенциальных правовых и финансовых последствий изменений.

Он отображает:

* выявленные потенциальные нарушения;
* уровень срочности;
* вероятность нарушения;
* финансовые риски;
* возможный диапазон штрафов;
* детальную информацию по отдельным изменениям.

В интерфейсе этот модуль обозначен как:

«Прогноз правовых и финансовых рисков для нанимателя». (GitHub)

🔎 Семантический поиск по базе НПА

В проекте предусмотрена база нормативных правовых актов с векторными представлениями.

Для хранения embeddings используется PostgreSQL + pgvector.

API предоставляет семантический поиск:

GET /api/npa/search?q=...

Поисковый запрос преобразуется в embedding, после чего система ищет наиболее релевантные статьи в векторной базе.

Можно указать количество результатов:

top_k = 1..20

Также предусмотрен endpoint со статистикой базы НПА. (GitHub)

🚀 Запуск проекта

Требования

Перед запуском необходимо установить:

* Docker
* Docker Compose
* Node.js 20+

Также потребуется API-ключ для AI-сервиса.

⸻

1. Клонирование репозитория

git clone https://github.com/art-petrovich13/hackathon_bsuir.git
cd hackathon_bsuir

⸻

2. Настройка окружения

Создайте .env из .env.example:

cp .env.example .env

Необходимо указать соответствующие значения:

POSTGRES_DB=npa_db
POSTGRES_USER=npa_user
POSTGRES_PASSWORD=npa_pass
DATABASE_URL=postgresql+asyncpg://npa_user:npa_pass@postgres:5432/npa_db
REDIS_URL=redis://redis:6379/0
GEMINI_API_KEY=your_api_key
SECRET_KEY=change_me_to_random_string
DEBUG=true

Конфигурация проекта также предусматривает отдельные переменные для секретного ключа, PostgreSQL, Redis и AI API. (GitHub)

Не добавляйте реальные API-ключи и другие секреты в Git.

⸻

3. Запуск backend-инфраструктуры

docker compose up --build

Docker Compose запустит:

Сервис	Назначение
PostgreSQL	Основная база данных
pgvector	Хранение и поиск embeddings
Redis	Очередь фоновых задач
FastAPI	Backend API
Celery Worker	Фоновый AI-анализ

Конфигурация Compose также содержит healthcheck для PostgreSQL и Redis, поэтому backend и worker ожидают готовности зависимостей перед запуском. (GitHub)

⸻

4. Запуск frontend

Перейдите в папку UI:

cd UI

Установите зависимости:

npm install

Запустите development server:

npm run dev

Frontend использует Vite, поэтому после запуска приложение доступно через локальный development server. (GitHub)

🔌 API

Основные группы API:

Upload

POST /api/upload

Загрузка и обработка PDF/DOCX документов.

Compare

POST /api/compare
GET /api/compare/{comparison_id}

Создание сравнения и получение результатов.

WebSocket

/ws/compare/{comparison_id}

Получение обновлений состояния анализа.

NPA

GET /api/npa/search
GET /api/npa/stats

Семантический поиск и статистика базы НПА.

Документация

После запуска backend:

http://localhost:8000/docs

Swagger UI:

http://localhost:8000/redoc

FastAPI автоматически формирует документацию API для проекта. (GitHub)

📌 Текущий статус

Основной pipeline проекта включает загрузку документов, структурный парсинг, создание задачи сравнения, фоновый анализ и отображение результатов в интерфейсе.

Некоторые части проекта находятся в процессе разработки. Например, backend endpoints для генерации и скачивания .docx-отчёта пока помечены как TODO и возвращают 501 Not Implemented. (GitHub)

Поэтому README намеренно не представляет генерацию готового .docx-отчёта как полностью реализованную функцию.

🎓 О проекте

Проект создан в рамках хакатона БГУИР и объединяет разработку frontend, backend, работу с документами, асинхронную обработку задач, базы данных и AI-анализ.

Основная идея проекта — сократить время ручного поиска изменений между версиями нормативных документов и предоставить пользователю не только список отличий, но и их семантическую интерпретацию с оценкой потенциальных рисков.
